# 架构说明

## 设计原则

1. **本地优先：** Markdown 是信息来源，可以用任何文本编辑器阅读。
2. **链接代替迁移：** 现有目录继续保持原有归属和结构。
3. **规则与状态分离：** `AGENTS.md` 保存稳定规则；`*.local.md` 保存个人信息和经常变化的状态。
4. **先讨论再排期：** AI 与使用者先明确目标和限制，再形成路线。
5. **用证据判断掌握：** 以实际表现判断进度，不以阅读数量判断。
6. **逐步增加结构：** 只有真实需求无法表达时，才增加新的领域或文件。

## 语言约定

- 给人阅读和填写的说明、模板与状态文件使用中文。
- 专门用于约束 AI 行为的 `AGENTS.md` 使用英文。
- 文件名和项目状态枚举保留英文，便于 Git 和不同 AI 工具识别。
- 同时服务人和 AI 的状态文件以人的阅读体验为主，使用中文；AI 通过 `AGENTS.md` 获得处理规则。

## 上下文层级

```text
根目录 AGENTS.md
  -> 私有个人背景和总览
  -> introduction/INDEX.local.md 指向的阶段自述与后续决定
  -> 领域 AGENTS.md
  -> 私有领域状态与知识状态
  -> 链接的原始资料
```

根目录指令规定 AI 如何跨领域工作，领域指令进一步细化方法，本地状态提供当前事实且不会暴露到 Git。

## 行动反馈与知识状态

学习者可以按自己的节奏行动，再用自然语言报告完成内容、结果和卡点。AI 将报告写入当周日志，把任务进度同步到领域 `STATUS.local.md`，并在确有概念证据时更新 `KNOWLEDGE.local.md`；学习者不需要手工选择这些文件。随后 AI 依据近期期限、当前优先级和最早未解决的知识前置点，给出一个主要下一步及可检查的完成标准。

`STATUS.local.md` 回答“当前在做什么”，`KNOWLEDGE.local.md` 回答“哪些概念已有何种证据、误区在哪里、下次从哪里教”，每日记录回答“实际发生了什么”。知识状态只在有解释、解题、代码、实验或迁移应用等证据时改变；教程应复用已证实的知识，并针对记录中的缺口展开。

## 公开框架与本地实例

公开仓库只保存规则、领域定义、模板和设计文档。本地实例由 `*.local.md` 以及被整体忽略的私有目录构成，包含具体身份、路径、日程、目标、进度与学习证据。GitHub 上缺少这些文件是预期行为，不表示框架不完整。

根目录 README 负责解释安装与日常使用，本文件解释数据职责和扩展原则，`templates/README.md` 说明模板到私有文件的映射。三者均不得复制本地实例中的个人内容。

## 阶段自述与日志

`introduction/` 保存学习者每阶段的原始自述，整个目录被 Git 忽略；其中的文件仍使用 `.local.md` 后缀。`INDEX.local.md` 指向当前阶段原文和后续确认记录。新阶段建议使用带完整年份的文件名 `YYYY-MM-DDINTRODUCTION.local.md`，既有文件不必改名。

自述提供背景，Dashboard 和领域状态提供当前行动；冲突按最新明确陈述与有日期的确认决定处理，不按文件修改时间判定。原始回答不被 AI 重写，自评不等于掌握证据。以后每次重要会话按根目录规则读取当前阶段。

每天在 `reviews/YYYY-Www-daily.local.md` 追加短日志，周末总结至 `reviews/YYYY-Www.local.md`。后续会话优先读取最近周复盘和当前周日志，历史原文保留供按需追溯。提醒导出文件放在被忽略的 `reminders/`；导出与实际启用是不同状态。

## 协作工作日志

`worklog/YYYY-MM.local.md` 记录 AI 与学习者完成的重要协作：确认的决定、产生的材料、已做验证和待办。它与每天的学习反思不同：前者回答“这次协作改变了什么”，后者回答“学习者今天实际做了什么和感受如何”。

工作日志按月追加且保留历史；后续纠正以新的日期条目说明，不改写旧条目。它只写有结果的工作，不记录每次搜索、命令或原始对话。`worklog/` 整个目录被 Git 忽略，索引文件让后续 Codex 能在启动时读取当前工作记录。

## 增加一个领域

用 `areas/<领域>/AGENTS.md` 保存稳定规则，再根据 `templates/area-status.md` 创建 `areas/<领域>/STATUS.local.md` 保存个人状态。只有积累了足够的概念级证据时，才创建 `KNOWLEDGE.local.md`。只有该领域存在活跃目标或确实需要持续关注时，才把它加入总览。

## 状态词表

项目状态只使用以下几种：

- `exploring`：正在明确是否要做以及为什么做。
- `planned`：已经定义结果和下一步。
- `active`：正在投入精力。
- `waiting`：正在等待外部事件或依赖。
- `paused`：有意暂停。
- `complete`：目标结果和完成证据已经记录。
- `review`：知识或习惯需要复查。

知识掌握程度使用：`初识 -> 能解释 -> 能在帮助下应用 -> 能独立应用 -> 待复习`。
